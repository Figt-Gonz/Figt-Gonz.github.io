01 / THE MENTAL MODEL

暂停的是任务，释放的是线程。

协程是一段可以挂起、稍后恢复的计算。它执行时仍然需要线程；等待时，则有机会让出线程。

01

线程 · 执行资源

在 JVM 上，由操作系统调度。阻塞会让这个线程暂时无法执行其他任务。

协程 · 可暂停的任务

由代码和运行状态组成。挂起后保存进度，恢复时接着向下执行。

并发 · 任务交替推进

一个线程也能并发。多个任务在多个线程上同时执行，才涉及并行。

suspend 是能力声明。它允许函数挂起，不会自动启动新协程、切到后台，或把阻塞 API 变成非阻塞。一次 suspend 调用也可能直接返回，完全不挂起。

异步 API 的回调持有 continuation，完成时恢复它。接入需要支持取消的回调 API 时，通常使用 suspendCancellableCoroutine，并通过 invokeOnCancellation 注销回调或取消底层请求。恢复应当遵守一次性约定；suspendCoroutine 本身不提供 Job 取消集成。

03 / WHERE & HOW

谁来管理？到哪里执行？

Scope 划定生命周期，Job 表达任务关系，Dispatcher 决定执行安排。它们通过 CoroutineContext 协同工作。

03
UI EVENT LOOP

Dispatchers.Main

把任务安排到 UI 主线程，适合更新界面与短时逻辑。耗时计算或阻塞操作会卡住界面。

UI / Main
withContext(Dispatchers.Main) {
  render(profile)
}
CoroutineContext =Job+Dispatcher+CoroutineName+ …
Context 是按 Key 组织的元素集合，右侧同 Key 元素覆盖左侧。launch / async 通常继承上下文并创建一个新的子 Job；没有调度器时才使用 Default。
切换上下文，不等于必然切换物理线程。例如 JVM 上的 IO 与 Default 共享底层线程。withContext 会等待代码块完成后返回，后续代码回到调用方上下文；单个协程挂起前后也不保证使用同一条工作线程。

父取消 → 子取消
普通 Job 和 SupervisorJob 都遵循。清理过程结束后，任务才真正完成。
子正常取消 ↛ 父失败
CancellationException 表示正常取消控制流。取消一个子任务通常不影响其兄弟。
Supervisor 隔离直接子任务失败
直接子任务失败不连带父与兄弟。子任务内部的普通 Job 层级仍按普通规则传播。

    
异常处理的关键区别：async、try/catch 与 CoroutineExceptionHandler
async 将异常保存在 Deferred 中，await() 会重新抛出；但在普通父子关系下，失败仍会取消父任务，不能理解成“只有 await 才会产生影响”。join() 不会像 await() 那样交付子任务的业务异常，但调用者自己被取消时也可能抛出取消异常。
要恢复业务错误，在执行任务的协程内部使用 try/catch；或者在 coroutineScope 外捕获整组任务的失败。try { launch { … } } 不能捕获以后在 launch 内发生的异常。
CoroutineExceptionHandler 处理符合条件的未捕获异常，例如根 launch 或受监督的 launch 子任务；它用于报告，无法让已经失败的协程继续执行。SupervisorJob 只隔离传播，不会自动处理异常。

分批动画仅模拟工作协程接收到外部取消后的行为；浏览器没有运行 Kotlin，也没有执行真正的 CPU 忙循环。
01CPU 循环主动检查
ensureActive() 检查取消并抛异常；isActive 可用于循环条件。yield() 还会给其他协程运行机会。检查本身不等于让出线程。
02用 finally 做清理
取消会沿异常路径展开，执行 finally。cancelAndJoin() 会发出取消并等待清理完成。清理中确需挂起时，可小范围使用 withContext(NonCancellable)。
03别吞掉取消异常
宽泛的 catch (e: Exception) 可能捕获取消。应先捕获 CancellationException 并重新抛出，再处理业务异常。
04超时也依赖协作
withTimeout 用取消结束任务，不会把任意阻塞调用变成可取消。JVM 上可中断的阻塞代码可考虑 runInterruptible。

    
挂起、可取消与线程安全是三件事。自定义挂起 API 未必响应取消；协程并行访问 counter++ 仍有竞争条件。用 Mutex、原子操作或合适的线程约束保护共享状态。

带走这六句话。
01 / SUSPEND
挂起保存执行进度，让线程有机会去做别的工作。
02 / CONTINUATION
保存后续执行的信息；状态机让顺序代码可暂停、可恢复。
03 / DISPATCHER
决定执行安排；挂起和切线程没有必然对应关系。
04 / ASYNC
并发要显式组织；先启动独立任务，再等待结果。
05 / JOB TREE
父等子、取消向下；普通子任务失败会影响父与兄弟。
06 / CANCELLATION
取消依赖协作；主动检查，用 finally 释放资源。

    
继续学习：Flow、Channel 与同步原语
Flow 适合表达异步值流，普通 flow {} 是冷流，开始收集才执行；StateFlow / SharedFlow 是热流。Channel 提供协程之间的发送与接收，缓冲容量影响发送方何时挂起。Mutex 用于保护共享状态，等待锁时可以挂起。
这些库抽象都建立在挂起、上下文与取消之上。掌握本页核心机制后，再学习它们的缓冲、背压、生命周期与异常规则。
